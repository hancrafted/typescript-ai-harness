# E2E results — ai-harness-setup harness `verify` gate

**Date:** 2026-07-17
**Tool under test:** `github:hancrafted/ai-harness-setup` @ `3db58cf` (== `origin/main`, == this worktree HEAD)
**Environment:** Node v24.18.0, npm 11.16.0, vitest 4.1.10, macOS. Worktree `worktree-harness-e2e`.
**archgate:** excluded from every selection (per instruction) — so no `.archgate/` is scaffolded and `verify` never carries `archgate check`.

## Method

Two phases, matching the two install vehicles the tool supports.

- **Phase 1 — real published path.** `npx github:hancrafted/ai-harness-setup` driven end-to-end through a pseudo-tty (`e2e/npx-selfhost.exp`), because the CLI is interactive-only (clack; no `--yes`). Installed the harness **into this worktree itself** (self-host, ADR-0003). Selection: deselect archgate → eslint + prettier + vitest + husky, all sub-option defaults, confirm.
- **Phase 2 — deterministic matrix.** Fresh `git init` targets under `/tmp/harness-e2e/*`, installed via the tool's documented non-interactive seam `run(answers, { cwd, exec: realExec })` (`e2e/install.ts`), which runs the *real* pipeline (real `npm install`, real `npx husky`). Then one orthogonal failure injected per installed check (`e2e/matrix.sh`).

> **Design fact used throughout:** `verify` / `verify:commit` are emitted by the **husky** integration, so a selection without husky has *no* `verify` script. Every Phase-2 case therefore includes husky; `verify` then composes only from the *other* selected integrations (US-35), which is exactly what's under test.

**Findings (logged, not fixed — per instruction):**
1. **No violations in the tool's own code.** Contrary to the expectation that "code created so far might violate it," the self-hosted `verify` is fully green. Clean dogfooding — nothing to fix, nothing suppressed.
2. **`prepare` guard clobbered by self-host (known tension, confirmed live).** The self-host merge overwrote the committed guarded `prepare: "husky || true"` with plain `prepare: "husky"`. This is the ADR-0001 vs ADR-0003 / US-36 tension already on record — the tool cannot self-apply without stripping its own npx-from-git guard. **Reverted in this worktree; not committed.**
3. **Idempotency held.** The four tool-owned configs regenerated byte-identical to the committed versions (no diff); only `package.json` changed and `.husky/` was newly created.
4. **`core.hooksPath` side effect handled.** husky set the *shared* `core.hooksPath=.husky/_` (worktrees share git config). Snapshotted before (unset) and restored to unset after — the main checkout is untouched.

## Verdict

- **Phase 1:** the published `npx github:` path installs the full harness end-to-end and the tool passes its own harness green (clean self-host). One known design tension (prepare-guard clobber) reproduced live.
- **Phase 2:** `verify` fails precisely on the broken dimension and passes otherwise, across four selections; the composed script contains **only** the selected integrations' checks (`tsc --noEmit` always present, by ADR-0007); `eslint-config-prettier` is composed only when both are selected; and the husky pre-commit gate blocks a red commit while letting a green one through.

**No defects found.** All deviations noted are pre-existing, documented design decisions (verify owned by husky; prepare-guard/self-host tension), not bugs in this behavior.
